<h2>直播配置的核心是「让上行稳定」</h2>
<p>直播跟录播最大的区别是实时性：录播可以重传，直播掉了就是掉了。所以配置的重点不是把带宽堆到最大，而是让上行持续稳定，并给波动留出缓冲。理解这一点，参数怎么调就有方向了。</p>
<p>先明确链路结构：推流软件 → 本地网络 → 出口（住宅或专线）→ 平台接收端。任何一个环节不稳，观感都会受影响。下面按「出口选择、推流参数、缓冲策略、验证方法」四段讲。</p>

<h2>出口：固定地址优先于高带宽</h2>
<p>直播账号同样有环境记录。地址在开播前后变化，容易引起额外验证。所以第一条要求是「固定」，其次才是带宽。住宅静态地址适合单账号短时长直播；专线适合多路并发与长时间直播。</p>
<p>如果业务既需要住宅来源、又需要稳定上行，可以选「住宅出口 + 优化线路」的组合，由服务方保证链路质量。采购时明确问清是否支持这种组合，很多方案只提供其中一种。</p>
<p>开播前必须验证：回显地址正确、解析地与出口同区、连续上传测试能维持目标码率。三项都过再开播。</p>

<p>码率是最需要保守的一项。很多人把码率设到上行能力的极限，结果网络稍有波动就掉帧。留三成余量，观感反而更稳。分辨率与码率要匹配：高分辨率配低码率，画面会出现明显的块状与拖影，不如降低分辨率。</p>

<h2>缓冲与重连</h2>
<p>推流软件的缓冲设置决定了抗抖动能力。缓冲太小，网络一抖就断；缓冲太大，延迟升高，互动变慢。直播带货这类需要互动的场景，延迟比画质更重要，缓冲不宜过小也不宜过大，按实际互动节奏调。</p>
<p>自动重连要开启，但重连次数不宜过多。频繁重连会让观众反复中断，体验比直接结束更差。重连失败后应检查链路，而不是反复点击开始直播。</p>

<h2>设备侧的准备</h2>
<p>编码占用 CPU 或显卡资源，服务器或电脑配置不足时，编码本身就会成为瓶颈，表现为画面卡但网络正常。判断方法：看推流软件的资源占用，若编码器长时间满载，就该降低分辨率或使用硬件编码。</p>
<p>另外关掉与直播无关的后台任务，尤其是同步盘、自动更新、大文件上传。这些任务会抢占上行，在直播这种持续占用上行的场景里影响明显。</p>

<h2>开播后的监控</h2>
<p>开播前十分钟是风险最高的时段，建议盯着推流软件的实时数据：码率是否稳定、有没有掉帧、延迟是否在合理区间。出现异常先降码率，再查链路。降码率能立刻缓解上行压力，是最有效的应急手段。</p>
<p>整场结束后记录一次数据：平均码率、掉帧次数、断流次数。连续几场对比，能提前发现链路劣化，而不是等到观众抱怨才处理。</p>

<h2>常见问答</h2>
<h3>住宅 IP 能直播吗</h3>
<p>可以，单账号、短时长、画质要求不极端时够用。多路并发或长时间直播，建议用专线或优化线路，避免上行不足。</p>
<h3>为什么直播卡但网页正常</h3>
<p>网页是短连接、小流量，对抖动不敏感；直播是持续上行，对上行带宽与抖动都敏感。两者表现不同是正常的。</p>
<h3>需要用专门的推流机吗</h3>
<p>画质要求高、需要多平台同时推流时，独立推流机更稳。单平台、中等画质，普通电脑或服务器足够。</p>
<h3>开播前多久完成配置</h3>
<p>建议提前一天配好并做完整验证，开播前只做最后检查。临时改配置，出问题时没有时间排查。</p>
